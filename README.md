# SingVerse 网页前端

本仓库独立维护 Vue / TypeScript / Vite / Element Plus 管理页、亲友 H5 和客户端下载页。源码位于仓库根目录，依赖由 package-lock.json 锁定，正式版本由 GitHub Release 标签决定并通过 `SINGVERSE_VERSION` 注入，本地开发默认 `0.0.0`。

## 开发与检查

在本仓库执行 make frontend-setup、make frontend-dev。开发服务只监听本机，/api 默认代理 http://127.0.0.1:8080；通过 SINGVERSE_DEV_BACKEND 显式选择开发 NAS Go 服务。

- make frontend-check：类型检查和完整生产构建。
- make test：全部交互测试。
- make release：检查后生成 build/release/singverse-frontend.tar.gz 和 SHA256SUMS。

Node.js 要求见 package.json；使用 npm ci，不改全局工具。联调时另行启动 Go 仓库的主服务。浏览器只调用同源 /api，不直连 compute 或业务数据库。

## 页面与分发

- / 或 /admin/：公开首页；点击登录弹出窗口，管理中心的 hash 路由继续使用登录守卫。
- /party/：亲友点歌 H5。
- /downloads/：免登录只读客户端下载页。

管理端“客厅 → 客户端下载”与公开下载页复用组件，登录页也提供下载入口。两端分别显示可用版本、APK大小、ABI、最低系统和校验信息；读取失败可重试，缺包保持真实空态。二维码通过当前 NAS Go 服务生成；本机/回环地址会提示改用其他设备可达的 NAS 地址。

Vite 一次构建完整 dist，必须包含 admin、party、downloads 三个入口及所有资源。Go 仓库首次打包时解析最新正式前端 Release，并在组件锁中固定该版本，下载静态包并嵌入二进制，再与客户端 APK 一起组装平台镜像。前端仓库不构建管理平台 Docker。

登录窗口提供“记住密码”“自动登录”和“忘记密码”。记住密码由浏览器密码管理器处理，HTTP 局域网页面需在浏览器自身的保存提示中确认；应用存储只保存账号与选择偏好。自动登录在完整认证（含已启用的 MFA）后保持 30 天，重新打开首页先校验服务端会话再进入管理中心，退出登录会关闭此偏好。忘记密码使用部署主机生成的 15 分钟一次性重置码，页面内可查看和复制对应部署命令；重置保留 MFA 并撤销所有会话。完整协议见[登录与密码重置](contracts/auth-login.md)。

正式 GitHub Release 标签使用 `vMAJOR.MINOR.PATCH`，例如 `v0.0.2`。Actions 从标签注入版本，直接构建并发布完整静态包和校验文件，不运行测试、类型检查或 lint；固定资产不覆盖不同内容。普通 push/PR、草稿和 Pre-release 不执行发布。本地指定版本可用 `SINGVERSE_VERSION=0.0.2 npm exec -- vite build`，再以相同环境运行 `python3 scripts/package-release.py`。

完整品牌源素材在 [assets/branding](assets/branding/README.md)，部署图片已在 public/assets/brand，不依赖 CDN 或跨仓库源码。契约快照及来源见 [contracts/SOURCE.json](contracts/SOURCE.json)，以 Go 仓库为权威。相关技能从用户技能目录读取，仓库不内置副本。NAS、微信、真实手机和电视的可达性与安装兼容需要单独验收。

## 媒体库管理

管理侧 `#/library/media` 通过“加歌 → 歌曲来源”进入。以卡片展示少量本地目录和 WebDAV，不再显示筛选栏与分页表格；超过 100 个来源可继续加载。统一添加入口选择来源类型，本地目录通过服务端文件夹选择器选择，WebDAV 填写地址与可选凭据。选择器桌面左侧展示挂载与已保存位置，窄屏使用“快速前往”选择框，支持完整路径回车跳转、面包屑，以及服务端名称筛选与分页；点击文件夹整行进入，底部显示当前完整路径并通过“使用当前文件夹”确认，支持键盘 Enter/空格进入目录。新增本地库优先进入 `/media`，下载用途优先 `/downloads`，编辑保留原目录。名称留空时自动生成；文件名识别直接展示在来源表单中，定时扫描位于“更多设置”。扫描完成留在当前页，可点击“查看歌曲”进入对应来源。本地结果保留到离开页面，WebDAV 后台任务可恢复。详见[媒体库说明](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/media-library.md)。

新建 WebDAV 可直接勾选“从已导出的资料包入库”并选择完整 ZIP，主操作变为“保存并导入资料包”。来源先保存为不扫描、不自动提取、不开启定时扫描，再将所选文件交给后台导入面板上传、预览路径与显式确认；文字和附件保存后只核验目录与大小，复用共享资料。上传中保护关闭与站内离页，失败可复用原来源和所选文件重试；上传完成后可从任务中心返回。顶部更多操作中的“导入资料包”复用同一表单，普通添加的“保存并扫描”行为保持。

## 模块边界

采用按业务聚合的目录，每个 `modules/<业务>/` 自己维护 `routes.ts`；需要时在内部增加 `api/`、`views/`、`components/` 和 `types.ts`，不预建空目录。`app/router/index.ts` 负责组合路由、登录守卫和页面标题；`app/layouts/AdminLayout.vue` 负责导航及管理外壳。现有 hash 路径与双入口构建保持兼容，导航按日常任务重组。

页面调用本模块 API 适配器；跨模块账号状态和带 CSRF 的业务请求由 `core/auth` 提供。`shared` 只放通用能力，不引用业务模块或应用入口。模块不反向依赖 `app` 中的布局和路由实例；入口挂载路径工具归 `core/hosting/`，供路由和系统状态页复用。首页复用系统状态模块的健康卡片，避免复制健康请求与展示逻辑。测试引用实际所属模块，移动源码时同步更新 mock 路径。

当前没有为分包增加状态管理依赖、独立 npm 工作区或新的构建入口；新增页面沿用模块结构即可。

## 解析规则与解析方案

文件名识别及自定义规则已归入“歌曲来源”，不再作为独立分区菜单。来源卡片显示当前方案并直接进入调整；来源表单中的“试验与调整”在同一个窗口复用方案与规则编辑器，保留来源草稿和正在填写的凭据，仅保存在组件内存。选中方案后必须点“使用此方案并返回”，再保存来源才变更绑定；保存共享方案/规则影响之后的扫描，界面明确提示引用影响。来源、方案与规则的关闭/返回、切页及刷新均保护未保存输入；从自定义规则返回时重新加载规则库修订号。旧方案与规则 hash 地址跳转时保留全部查询参数及锚点。

“加歌 → 歌曲来源 → 文件名识别”（`#/library/media/recognition`）是日常使用的唯一主路径，页面按“填文件名 → 挑格式 → 保存”四步组织：第 1 步输入媒体文件名并点“找出能识别的格式”，一次 `POST /profiles/preview` 携带全部内置格式候选，按返回的逐条 `attempts` 判定哪种命名格式能识别；第 2 步把内置格式渲染成卡片墙（`button.format-choice`），标出能用、只认出一半、识别不了、已在方案里，点一下即追加为成员、再点移出，不再使用铺满页面的系统下拉；第 3 步是方案名称与保存；第 4 步“我要自己排顺序、启停，或用自定义格式”折进 `<details class="profiles-advanced">`，保留原有序成员列表、启停、`添加已有规则`（此处选项已收窄为非内置定义）、`解析当前方案` 与完整预览面板。主区不出现“规则”一词，用户可见名词统一为“格式”。检测只在点击时发起，不自动触发；改文件名只把旧检测结果标记为过期。方案保存无需示例命中；切换/离开/刷新保护未保存草稿，成员或输入变化标记旧预览，迟到响应丢弃，冲突时“加载最新配置，保留草稿”并标明失效引用。

“歌曲来源 → 文件名识别 → 高级配置 → 自定义规则”（`#/library/media/recognition/rules`）作为来源内高级页，只维护单条自定义定义和引用情况，新增/编辑直接编译校验保存；内置定义只读、可复制，改由方案页的格式卡片提供，页面顶部明确提示平时不需要来这一页并给出返回主路径的链接。方案复制不复制定义；共享规则修改影响所有引用方案。默认方案可改名和清空、不能删除，引用中的规则不能删除并列出方案链接。旧路由和三个旧 API 保留兼容，新数据按 schemaVersion=2 保存，媒体来源可绑定完整方案，本地扫描会使用已保存的启用成员顺序提取并保存歌曲数据。详见[规则与方案说明](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/filename-rules.md)。

## 管理页面布局与视觉主题

二级入口顺序为：曲库「歌曲、歌手、歌单、收藏」；加歌「歌曲来源、下载歌曲、缺歌心愿」；整理「歌曲信息、歌曲分类、原唱与伴奏」；客厅「播放与热门、电视首页、客户端下载」。各一级分区进入该分区的首个二级页面，手机全部菜单使用相同归属与顺序；文件名识别收在歌曲来源内，已有方案、规则和批次深链接继续兼容。

管理端采用「家庭音乐资料室」方向：中性表面、品牌蓝、真实歌曲封面与歌手照片。桌面保留顶部「首页 / 曲库 / 加歌 / 整理 / 客厅」与当前分区的二级导航，任务、助手、设置、外观和账号位于右侧；主导航 16px（窄平板 15px），二级导航及手机菜单 15px；手机使用带焦点限制、Escape 关闭和焦点恢复的全部导航面板。已有 hash 深链接、查询参数与登录目标恢复继续兼容。完整功能对应关系见[管理端体验设计](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/admin-experience.md)。

外观提供浅色（默认）与深色两套主题，通过顶栏及移动导航选择，仅保存在本浏览器的 `localStorage['singverse.admin.theme']`，不跟随系统、不写业务库。旧 `indigo/pine/vermilion/celadon` 偏好迁移为 `light`，`midnight/graphite` 迁移为 `dark`；非法值回退浅色，本地存储不可用不影响显示。挂载前同步应用主题。

`src/admin/app/styles.css` 为管理端入口，按职责引入 `styles/tokens.css`（浅色令牌与 Element Plus 变量）、`themes.css`（深色覆盖）、`element.css`（组件状态）、`controls.css`（原生控件）、`workflows.css`（共用业务布局）、`shell.css`（导航）及 `login.css`（登录）。模块内只处理业务布局。正文 14px、辅助文字 12–13px、登录等独立页面标题 28px；控件 40px，手机点击区域至少 44px。二级页面采用选定的 C「浏览优先」：`PageHeader` 以18px语义 `h1`、可选 `meta` 数量槽、主操作及说明图标组成轻量内容栏，不再保留大标题／副说明区或右侧孤立按钮行。说明按需展开，Escape关闭后回到原按钮；既有 props、actions／description 槽和业务事件兼容。筛选直接贴近列表，结果范围与显示／选择工具同组，低频整理与高级资料收进更多菜单，手机本页统计也由更多菜单按需展开；设置使用分隔条目，保存、批次控制仍留在各自表单和任务范围。文件名识别与自定义规则统一高亮「歌曲来源」，由来源卡片、来源表单或来源页更多操作进入，不额外渲染第三条全局导航。亲友 H5 不引用管理端样式；不依赖外部字体或 CDN，并尊重减少动态效果偏好。

首页取消独立大标题和副说明，浏览曲库、添加歌曲与刷新合并在紧凑入口条中，仍保留无障碍页面标题。首页通过只读聚合端点 `GET /api/v1/admin/overview` 一次读取歌曲数量、待复核、来源、最近入库、歌单、近 30 天播放与计算 / AI 就绪状态；每块独立采集，部分失败置空并单独提示，不把未知数量当作零。任务摘要仍按 10s 轮询 `/background-tasks`，仅在可见页面轮询，离开停止，服务端任务继续执行；顶栏徽章 30s 轮询 size=1。

歌曲默认封面浏览，随时切换高效列表；有效歌名与歌手优先，路径、文件与解析证据在详情和可选列展开。详情提供歌词、分类、音轨状态、试听与整理入口。单曲审核保持当前值 / 候选值 / 草稿区别，先保存到审核草稿，再明确确认应用。窄屏审核以「查找匹配候选 / 核对与编辑字段」切换，字段比较纵向展开，确认按钮保持可见。歌单编辑、AI 建议确认、失败重试标识与版本冲突保护继续生效，歌单增加离页及浏览器关闭草稿提醒。

视觉验收使用 1440×900、1024×900 和 390×844。截图是本地验收产物，不进入源码或 Docker 构建上下文；实际检查与真机边界见[验证记录](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/verification.md)。

## 歌曲管理

「曲库 → 收藏」（`#/library/favorites`）采用 A「共享清单」：歌曲封面、歌名/歌手、专辑和收藏时间构成连续列表，窄屏转为歌曲行。后台、手机和电视读取同一 NAS 集合，支持服务端搜索/筛选/排序、曲库多选添加、单首取消及当前页批量取消。已移除歌曲保留辨认信息与封面占位；取消只删除收藏关系。进入页面、恢复前台和写入后刷新，可见时约 30 秒轮询。读取失败保留上次成功内容并提示，保存失败保留确认选择；不读取或导入旧本地收藏。接口及认证边界见 [共享收藏契约](contracts/favorites.md)。

「曲库 → 歌曲」（`#/library/songs`）由 `modules/song-management/` 维护，读取同源 `GET /api/v1/media-songs`。顶部支持搜索范围、来源、多选分类标签、文件名识别状态及重置；旧链接的待复核、未分类、指定歌曲与页码保留。默认封面浏览，手机把来源、分类和识别状态收进可展开筛选区，并显示已应用条件数。列表模式提供显示列、紧凑密度、完整页内表格和内部横向滚动；两种模式切换不重新请求、不丢失本页选择。默认每页 20 首，可切换 50 / 100，翻页或重新查询清空本页选择；批量栏明确显示本页范围。总数、当前页范围和本页统计分别表达。

默认搜索使用新参数 `search`，在 Go 内按有效歌名、歌手或相对路径作不区分大小写的字面子串匹配，筛选与总数计算在分页前完成，沿用扫描时间倒序、ID 正序。只采用有效字段，过期 / 未确认的候选不会冒充有效身份。旧 `q` 仍仅匹配相对文件路径；旧 `?q=` 链接自动选择「文件路径」，两者与来源、标签等筛选可组合。浏览器不拉取全曲库做本地筛选。服务端复用指纹与来源投影，流式检查符合 SQL 范围的记录，仅保留当前页；特别大的曲库中，身份搜索仍有线性投影成本，尚无额外全文索引。

歌曲查询的迟到响应不会覆盖新筛选。空库引导添加来源，失败提供重试；详情与播放器保留既有释放、切歌、音轨位置与实时兼容播放流程。原媒体只读，播放、元数据、分类、缓存操作仍由原有 API 与版本保护执行。

## 元数据刮削

歌曲行可打开候选审核弹窗，勾选歌曲可进入批次页。「整理 → 歌曲信息」统一匹配与审核入口：上方集中显示匹配范围、平台摘要和批次进度，下方用全部、待审核、已应用、失败及更多状态筛选同一批歌曲。待审核为零仍保留入口并提供空态；原 `#/library/review` 链接保留批次、歌曲选择和锚点，自动进入歌曲信息页的待审核视图。批次内审核采用右侧抽屉，手机使用全屏审核；逐字段确认、候选切换、手工编辑、封面选择与未应用草稿提醒沿用单曲工作区，曲库原有编辑弹窗保持可用。「设置 → 音乐平台」（`#/system/music-platforms`）集中管理平台选择、自动应用、相似度阈值和请求间隔；审核中的「管理平台」与批次工具栏的平台摘要直达设置，保留原页面返回地址。配置保存失败、离页与刷新保护草稿。可选择全部媒体来源或指定媒体来源刮削，所选歌曲仍可单独创建批次。`modules/metadata/` 维护界面、API 和类型，路由 `#/library/songs/metadata`，受管理员登录保护；新安装默认启用网易云、QQ、酷狗、酷我和汽水五个平台，自动应用默认关闭，匹配阈值默认 80%；升级保留已有保存的选择，真实状态由后端保存。进度按需轮询，离开页面停止；重新打开读取最近批次。详情同时保留文件名解析证据，已确认字段优先展示，失效结果标明文件变化。见[元数据刮削](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/metadata-scraping.md)。

批量刮削可在平台设置中配置每首完成后的等待范围（默认 1～2 秒，允许 0～300 秒，含端点；最大值不得小于最小值）。设置持久化且保存时暂停活动批次，续跑使用当前间隔；等待不占用数据库连接。同一平台请求仍保持串行及至少 1.5 秒启动间隔；HTTP 429 会触发该平台至少 60 秒冷却，期间拒绝新请求，失败项可稍后手动重试。单曲搜索也受平台冷却约束，批量间隔只约束后台批次。设置为 0 秒表示不额外等待，但任务调度约每秒检查一次，同平台仍受请求启动间隔约束。随机间隔用于平滑流量，不能保证避免限流或自动化识别。

歌曲列表使用独立搜索区、桌面列表/手机卡片及可选每页条数；媒体库页面使用卡片，来源列表 API 仍保留名称/地址、类型、方案筛选能力，查询使用 ID 分页后延迟关联和筛选排序联合索引。深分页成本与包含搜索边界见[列表查询说明](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/library-search.md)。

媒体来源添加/编辑支持定时扫描开关及标准五段 cron（上海时区）；配置与下次触发持久化，同来源扫描中跳过，停机遗漏不逐次补跑。使用及 API 字段、调度限制见[定时扫描](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/media-scan-schedule.md)。

单曲元数据已使用独立双栏审核工作台，支持字段编辑、受管 JPEG/PNG 上传、网易云 / QQ / 酷狗 / 酷我 / 汽水封面搜索及统一确认应用；封面窗口可选原图或高清，显示实际像素，选择随确认保存；旧批量审核入口保持独立。新增接口、资源备份、幂等与版本校验规则见[单曲审核](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/single-song-review.md)。

批量工作台已统一整体进度：total/completed 均包含跳过项，新批次持久化跳过明细，旧批次仅汇总并提示。新增批次内搜索/排序、可信度审核提示及按状态操作，自动写入改为第一候选达到有效阈值即执行；限流规则不变。接口兼容说明及统计定义见[批量工作台](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/batch-metadata-workbench.md)。

歌曲分类通过「整理 → 歌曲分类」（`/library/classification`）进入，包含词表维护、输入预览、分类任务、人工审核与变更撤回；模型服务、启用开关和请求间隔在 AI 设置独立管理；歌曲列表支持分类筛选和批量打标。详见[分类说明](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/song-classification.md)。


歌曲列表对文件名解析“待复核”的歌曲显示“复核”按钮，详情中也提供入口，均复用现有单曲元数据审核工作台，可手工编辑或搜索候选，勾选字段后确认应用。完整匹配歌曲保留“编辑”入口。元数据确认仍保存到独立覆盖层，文件名解析状态及待复核筛选语义不变；工作台明确说明这一区别，不修改原媒体。


歌曲筛选区的分类筛选使用可搜索、多选、可清空的下拉框；选中标签折叠显示，避免原生多选列表撑高筛选区。筛选控件居中对齐，窄屏换行，查询与重置行为不变。


## 管理端在线播放

歌曲列表行内“在线播放”打开简洁播放器，仅展示歌名与媒体画面，音频和视频共用一套进度、播放/暂停与音量控件。底部常驻原唱/伴奏和编码选择（自动、原始编码、H.264/AAC 兼容；纯音频使用 AAC），画质与字幕收进“设置”，没有可调选项时隐藏设置入口。兼容播放统一通过编码选择，不再提供单独的兼容版本生成、任务列表或批量转换入口。切换保留播放位置及播放/暂停状态；原始编码直接读取源媒体，遇到需要选轨、改变画质或字幕的操作时回到自动处理，避免默认音轨冒充已确认的角色。关闭弹窗或离开页面停止并移除媒体源、取消后台会话；错误时可使用兼容编码重新加载。

原唱/伴奏使用曲库共享的角色标记；伴奏未确认或未生成时禁用按钮。独立生成的伴奏通过 Go 授权地址读取，视频原声静音并按原时间轴偏移同步进度、暂停、音量和缓冲；纯音频直接播放伴奏文件。切换可能需要重新协商和缓冲，实际浏览器解码及长时间音画同步仍需使用真实媒体验收。

自动编码遇到浏览器解码失败或格式不支持时，内部仅重试一次 H.264/AAC 兼容播放，保留位置、角色、音量及播放意图；仍失败才显示实际错误。手动选择原始编码时不自动转码，网络读取失败单独提示。关闭或替换媒体产生的取消事件不视为解码错误，每次加载使用独立媒体元素和执行标记，忽略旧媒体与 HLS 回调。

`GET /api/v1/media-songs/{id}/video` 与 HEAD 复用管理员 Cookie 会话，未登录返回 401，不提供公开媒体 URL。支持单段 Range（起止、开放结束、后缀范围），本地响应 200/206/416 和 Content-Length/Content-Range；非法范围或多范围返回 400。流响应禁止浏览器/公共代理缓存，NAS 内部的受控原片缓存独立管理。本地解析真实路径并限制在来源目录内，失效文件或越界符号链接返回 404。

WebDAV 使用保存的地址和加密凭据在服务端发起 GET/HEAD，不把凭据或远端地址返回浏览器。NAS 按需保存原片块，命中部分直接读取，缺失部分流式回源，不必等待整首缓存完成；完整块与兼容播放缓存共用容量和清理策略，缓存失败时仍可回源播放。上游连接超时 10 秒、读取空闲超时 30 秒，结束或取消关闭连接。GET 忽略非零/后缀 Range、206 的范围/长度不一致、压缩正文均拒绝；零起点 200 与 HEAD 忽略 Range 仍允许。不跟随 3xx（返回 502），需要支持直接 GET/Range 的 WebDAV 服务；认证/读取错误返回不含远端细节的 502。

原始媒体接口继续直放；播放弹窗另通过 Go 协商 HLS 或兼容版本，浏览器不直连 Python，也不因预览创建电视会话。浏览器能否解码取决于容器与视频/音频编码，MP4/WebM 也不保证所有编码都能播放，MKV/AVI 等可能不可播放。Go直接流式返回媒体；使用外部反向代理时应关闭媒体缓冲和缓存，并支持Range、HEAD及足够的读取超时。真实 NAS、WebDAV 提供者、浏览器编码兼容性仍须单独验收。


## 音频文件扫描与在线播放

本地目录与 WebDAV 文件名扫描统一支持 MP3、FLAC、WAV、M4A、AAC、OGG、OGA、Opus、WMA、AIF、AIFF、APE，扩展名不区分大小写，沿用现有解析方案提取歌名和歌手。扫描只建立文件名索引，不读取音频内容或内嵌标签；新增格式需重新扫描才会进入歌曲列表，现有扫描数量限制不变。

“在线播放”按扩展名选择音频/视频控件。音频复用已鉴权的 GET/HEAD `/api/v1/media-songs/{id}/video`（为兼容保留原路径），返回 audio/* 媒体类型，沿用 Range、后端 WebDAV 代理、凭据保护与关闭停止加载。音频失败可重试，切换或关闭时移除旧媒体元素。不能直放时可使用兼容播放或离线版本；实际支持取决于 compute 工具与源编码。WebDAV 下载重定向限制不变。


## AI 配置中心

设置依次包含音乐平台、存储与缓存、计算服务、AI 与助手、账号与安全、服务状态，默认进入音乐平台；头像菜单继续直达账号与安全。AI 设置仅提供模型服务、搜索服务、功能配置三个页签，路由为 `/system/ai/models`、`/system/ai/search`、`/system/ai/features`，`/system/ai` 重定向模型服务。应用导航不增加第三层入口，歌曲分类位于整理。

`src/admin/modules/ai-settings` 独立管理共享服务与功能绑定；分类模块仅读取兼容配置摘要并跳转到功能配置。多个服务可使用同一厂商；模型地址支持根地址、带版本的 API 基础地址（如 `/v1`）或完整调用地址，并展示实际请求地址。模型 ID 支持“获取模型列表”后搜索选择，也可手动输入。获取使用当前未保存的地址、协议和密钥，经同源 Go `/api/v1/ai/models/discover` 获取候选，不自动保存或生成；编辑已有服务可复用同一目标的已保存密钥，切换连接配置或关闭表单后丢弃迟到结果。目录失败或为空时保留手填和现有选择。Schema、JSON 模式及超时收进“更多设置”；普通生成、工具调用、分类结构化输出及搜索查询测试分别验证已保存配置。搜索结果只展示标题、链接、摘要及耗时，不抓取正文、不用于分类。

编辑密钥留空表示保留，读取接口仅返回 `hasKey`。厂商、协议或地址改变时必须重新输入或明确清除原密钥；被绑定的服务需先替换或解除绑定才可停用或删除。页面和表单离开时保护未保存修改，窄屏弹窗内部滚动。详见 [AI 设置](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/ai-settings.md)。


AI 设置的功能配置新增独立 AI 助手页 `/system/ai/features/assistant`。可启用全局管理页右下角助手并选择宠物/聊天框形态；默认关闭、服务端保存，当前仅展示能力规划。宠物目录 `ai-settings/pets.ts` 独立于助手交互；内置音符团子 SVG 及 13 款透明底 PNG（05 熊猫、31–36 二次元、37–42 科幻），通过自适应网格选择，随前端打包无需外部图片服务；编号沿用候选图。对话和工具调用尚未开放，亲友 H5 不显示。


解析方案底部的“方案与保存”采用独立名称标签、保存状态和按钮布局，数量摘要显示启用/停用格式；高级配置提供有间距的执行顺序、添加规则和草稿预览区域。窄屏按钮与添加控件自动换行，不改变方案保存、排序及启停行为。


歌曲分类已按普通用户流程重做：开始分类负责选歌、选择分类内容和确认输入；分类记录集中处理进度、审核、重试与人工整理；分类词表独立维护标签。结果使用适配手机的歌曲卡片，确认时比较前后分类。保留原 songIds/task 查询参数、接口和全部业务保护；自动保存默认关闭，高级选项中显式开启。共享结果展示组件为 `ClassificationResultCard.vue`，页面样式单独放在模块 `styles/classification.css`。


歌曲分类的“选择歌曲 / 重新选择歌曲”均在当前页打开 `ClassificationSongPicker.vue` 弹窗。支持同源接口搜索、分页、选择本页、跨页勾选及 5000 首上限；列表内部滚动，搜索、分页和确认按钮固定可见。确认后更新兼容 songIds 查询参数并保留分类选项，取消只丢弃弹窗选择草稿。

AI 助手的宠物和聊天框入口支持鼠标/触屏拖动，移动超过6px才识别为拖动并抑制松手点击；位置限制在当前窗口内，缩放窗口或切换形态后重新约束。展开面板根据入口位置向上或向下显示。位置仅在当前管理页会话保留，刷新恢复默认入口位置。

歌曲复核展示以有效确认的核心信息为准：歌名和歌手均勾选确认、非空且元数据未失效后，列表/手机卡片显示“歌曲信息已复核”，操作改为“编辑”，本页统计计入已复核。仅确认专辑、时长或封面不解除原有复核提示。详情保留原始文件名解析证据，旧 status=REVIEW 查询仍匹配原始解析状态。

本地媒体库扫描读取音视频内嵌歌名、歌手、专辑、发行日期，文件字段优先，缺失字段回退已确认信息/文件名。全部歌曲标识“优先使用文件内嵌信息”，审核提示内嵌字段会被保留；需要修改这些字段时编辑原文件标签后重新扫描。WebDAV继续只按文件名索引，不下载媒体内容。

### 性能节点配置

“设置 → 计算服务”（`/system/compute`）提供自动识别、独立部署、暂不使用三种模式；顶部以紧凑状态栏展示连接状态、部署方式、地址和操作，不展示功能介绍卡片、部署说明与页尾说明；随应用部署的服务自动连接，无需再次填写。视频播放加速与伴奏生成分为两个页签，按需加载设置并在切换页签时保留已打开的内容；未连接、停用或节点未提供相应能力时，展示准备提示，不读取硬件/模型接口。伴奏显示“可准备模型”仅表示接口可用，仍需在页签内完成模型和设备试跑。页签写入 `?tab=video|audio`，旧 `#audio-models` 链接进入伴奏页签。点击“编辑连接”才在连接状态下方展开配置：使用统一的启停开关、地址和密钥表单，部署地址自动填入，部署密钥只显示已配置并由服务端继续使用；修改地址或填写新密钥时按手动配置保存，不向浏览器返回部署密钥原文。停用时收起连接字段；切换启停保留草稿，统一点击“保存设置”生效。连接编辑使用独立的 520px 侧边面板，底部固定测试、取消和保存操作，主页面只保留状态和功能设置；面板内地址和密钥为主要字段，密钥获取帮助按需弹窗展示，目录映射与密钥管理默认折叠。独立部署支持加密凭据、最长根路径优先的媒体路径映射；新连接检查通过才保存并切换，失败保留原连接，并可明确选择仅保存离线配置。当前状态检查与编辑草稿分离，取消恢复原配置；离开未保存草稿有保护。客户端仅调用同源 `/api/v1/compute-node`，不直接连接 Python。配置只管理一个活动节点，不包含负载均衡或远程文件传输。

连接抽屉提供“扫描局域网内计算节点”，由服务节点执行扫描，默认使用其所在局域网网段及18090/8090端口。折叠的“指定扫描范围”可填写RFC1918 IPv4网段（/24～/32）与1～65535自定义端口，便于从localhost访问管理端或使用其他部署端口时连接真实局域网节点。扫描只展示节点名称、地址与配对状态，不改变连接草稿。点击“连接此节点”后由Go完成配对、认证与业务回源检查，成功才保存并切换，无需手填密钥，浏览器不接收节点密钥；未开放配对的节点显示原因并保留手动配置入口。

扫描可取消等待并忽略迟到结果；空结果和错误均可重试。有手动草稿时，选节点前确认是否放弃；配对失败保留当前连接、草稿和扫描列表，配置冲突可读取最新设置。扫描及配对使用管理员Cookie与CSRF保护的`POST /api/v1/compute-node/discovery`和`/pair`，配对仅传发现ID及revision。行为/API检查见`tests/compute-node-discovery.test.ts`、`tests/compute-node-discovery-api.test.ts`。

## 电视与亲友点歌

亲友遥控在服务端声明 `snapshotWaitMs` 时，使用带 `afterStateRevision` / `waitMs` 的快照长等待接收命令执行反馈；变更提交立即返回，最多等待 8 秒后续订，发送回执与电视执行结果仍分开显示。旧服务保留每秒轮询。收藏约每 5 秒独立同步，慢收藏请求不阻塞遥控；退出或换聚会取消挂起请求，旧快照和旧连接错误不能覆盖新状态。低延迟链路需同时更新 Go、TV 和 H5，细节见 [遥控契约](contracts/party-remote.md)。

电视端填写 NAS 地址和账号密码直接登录，管理端的电视连接与授权管理页面已移除。亲友 `/party/` 使用 fragment 邀请链接，预览不加入，显式确认后在 sessionStorage 保存本场独立参与凭据；不复用管理员 Cookie。成功加入后仅将昵称存入当前同源的 localStorage，下次打开或扫描其他场次时自动回填，仍可修改后确认加入；离开本场保留昵称，失败加入不覆盖已保存昵称，存储不可用时仍可正常加入。已有有效参与身份会自动补存昵称。同一 H5 供微信及 App 网页容器使用，App 断开电视时也保留昵称缓存，需使用已更新的手机端。点歌超时保留原请求 ID，提示先核对队列再重试；锁队、撤权和散场均由 Go 强制检查。视觉采用暖白与珊瑚橙。微信/App 真机与 NAS 网络另行验收。


### 分类封面

管理入口「整理 → 歌曲分类 → 分类词表」可点击缩略图或“上传封面/更换封面”，选择图片后预览并显式保存；移除需要确认。不需要启用 AI。新标签先保存到词表，再上传封面。建议16:9横图、主体居中，JPEG/PNG最多2,000,000字节、单边不超过4096像素；后端重编码为最长边1280像素JPEG并移除附加信息。预览为居中裁切，与TV的分类卡片一致。

上传/移除使用管理员Cookie及CSRF，封面有独立的coverVersion防止覆盖其他管理员窗口的新图片；409时关闭弹窗并点“刷新词表”重试。选择后未保存的图片不生效，上传中阻止重复提交，离开组件取消请求。封面不改变标签名、启用状态或歌曲归类。TV进入分类或约30秒刷新可见更新；标签停用后TV不显示封面，管理页仍可管理。

## 自动歌手库

扫描后按歌曲有效署名自动生成，不再人工建档/关联。管理端歌手详情可打开歌曲编辑器订正歌手，NAS 覆盖值优先于文件标签并在重新扫描后保留；恢复扫描值需确认。首次后台从网易云/QQ 核对歌曲并取真实歌手头像，失败有限重试，无可靠匹配保留占位。上传图片优先，移除后暂停自动补图。TV 自动展示同步结果和受权图片，保留返回焦点。相关结构已纳入首次部署基线 `202611070001`；新增接口、来源与状态见 OpenAPI 和 [自动歌手库说明](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/artist-library.md)。

歌手列表以头像封面为主，男歌手、女歌手、组合与待分类有常驻筛选和明确标记。可跨页选择后批量获取封面或标注类型；封面面板选择已选/全部筛选快照和图片平台，已有封面及手动移除设置保留。批次离页继续，在歌手页或任务中心查看真实结果；候选需确认，类型不自动推断，版本冲突整批回滚。详情独立保留背景图及头像生成的横幅预览，上传界面标明用途；具体范围、平台启用及增量数据库说明见歌手库文档。

## 共享歌单

「曲库 → 共享歌单」及歌曲管理快捷入口支持手动选歌、排序、编辑/删除与 AI 辅助创建。管理列表使用封面歌单卡片，支持名称/简介搜索及最近更新、名称、歌曲数量排序，条件由后端在分页前执行。AI 选择已配置启用模型，最多从 500 首候选中推荐 1～50 首，先预览并明确采用，再保存；无模型时可手动创建。复用歌曲选择器，歌单上限 500 首，跨页保留选择。实现与接口见 [歌单说明](https://github.com/mynora-dot/singverse-go-backend/blob/main/docs/playlists.md)。

性能节点页面新增“转码与硬件加速”，通过 Go 读取/测试/保存计算节点执行配置，支持恢复部署默认与按编码器查看探测结果；所有变更继续使用管理员会话和 CSRF。

硬件页面以独立设置区、当前生效摘要和节点能力表展示；当前方式优先，其他平台和部署说明默认折叠。素材试跑后的硬解、零拷贝、GPU 色调映射分别标记，CPU 仅显示软件处理；播放弹窗显示实际流水线。未试跑硬件显示“待验证”，不会沿用编码器存在这一条件宣称全链路可用。

## WebDAV 扫描与内嵌元数据

WebDAV 扫描按路径增量更新，卡片显示新增、复用、待确认删除、下架数量。缺失文件需间隔至少 30 分钟的两次完整成功扫描确认；突然空库保留索引，在“整理与分享”中单独确认全部下架，缓存保留 30 天。

WebDAV 来源卡片提供“内嵌元数据与分享”入口，弹窗主区域单列“获取内嵌元数据”，可直接开始、暂停或继续后台自动提取，也可试提取一首并查看样本结果；本地来源提供查看歌曲，空库提供扫描入口。重新扫描、访问组、代理地址、增量分享及单独下载分包保留在默认折叠的“高级选项”，不展示步骤导航、文件同步数量、读取流量统计或内部任务状态。

点击“导出分享包”后，由后台等待文件保存并生成快照，界面显示“正在准备”；关闭窗口不影响后台任务，完成后只提供“下载分享包”和重新导出。每包最多 5000 首、32 MiB 的拆分由系统完成。选中收到的整套 ZIP 后立即导入，无需先解压或再次点击开始；也支持按文件名顺序选择多个分包。整套上传最多 8 GiB，服务逐个处理有界分包，中断后重新选择即可继续，已有歌曲和人工订正不会覆盖。

本地和 WebDAV 的刮削采用、编辑及内嵌提取结果自动保存到统一服务衍生目录，原媒体及旁边目录保持只读。暂不可用的封面后台补齐，不阻塞正文保存或分享；较大封面自动缩小到受控附件大小。仅需要用户处理的操作失败在主界面显示简短提示，其余状态收进高级选项。

行为测试位于 `tests/embedded-metadata.test.ts`，覆盖主按钮启停、隐藏技术细节、后台等待、选择文件即导入、样本缓存复用及空库确认。共享核心信息仍显示“共享信息待核对”，确认后解除提示。模拟与浏览器验证不能替代实际 OpenList/网盘风控验收。

### 原唱与伴奏

管理员入口：整理 → 原唱与伴奏，页签为“歌曲 / 生成任务”，当前页签写入地址 `?tab=tasks`（旧 `setup` 跳转性能节点配置），支持方向键切换；页头状态标记显示伴奏生成是否就绪，点击进入性能节点配置。歌曲页按名称、歌手、媒体库、音轨数量筛选，并提供“可生成伴奏、待标记原唱、待识别、已有伴奏、生成中、生成失败、多音轨/无音轨”快捷状态（待标记原唱对应接口 `state=UNCONFIRMED`）。每行按状态给出一个主操作：生成伴奏、标记原唱、修改标记、试听伴奏或查看详情；点歌名打开该曲的音轨面板。跨页勾选或“选择全部 N 首”已应用筛选结果后生成；编辑筛选框但未搜索不会改变选歌范围。确认框说明将生成、先读取音轨及跳过的数量和原因，确认后由 Go 保存快照，默认跳过已有成果/处理中/非单音轨，待探测歌曲确认为单音轨后进入分离。生成任务显示进度、剩余与失败数，详情抽屉列出每首结果；停止进行中的任务或单曲需要二次确认，失败项可重试；允许主动选择合格 CPU，失败项按原配方重试，已完成成果保留。

单曲音轨面板（原唱与伴奏页抽屉）按音轨数量显示：双音轨用单选“哪一条是原唱”，另一条自动作为伴奏，音轨显示为“音轨 1 · AAC 立体声 · 语言 · 标题”而非源 ID；AI 自动标记可一键确认为人工标记；单音轨可生成、重新生成或在线试听独立伴奏；未读取的歌曲可读取音轨。编辑时轮询不会清除未保存选择，面板关闭后停止轮询。歌曲详情抽屉显示该曲当前原唱/伴奏状态，并直达对应歌曲的音轨面板。亲友 H5 歌曲行可展开“纠正原唱/伴奏”，已加入聚会的亲友可提交全曲库订正；未确认的双轨保持“待确认”，没有模型时也能通过技术探测后人工标记。角色按源 stream ID 保存，纠正不替换当前正在播放的媒体。

双音轨 AI 返回不确定时显示具体原因（人声差异不足、片段方向冲突、标签冲突等），提供“重新分析”，兼容没有证据字段的旧结果。新分析的能量比、采样位置和分析版本放在默认折叠的“识别依据”，不把数值展示为准确率；当前人工/共享标记仍优先。任务运行中复用同一任务，已得到明确结论的分析继续复用，不确定分析由 Go 创建新任务，不清空旧处理记录。

性能节点配置集中展示连接、实际硬件与执行策略、伴奏模型及设备试跑；每个模型单独提供下载、离线导入及离线文件校验信息，可选择基准 htdemucs 或 Intel 官方 OpenVINO 转换模型。页面只保留模型准备和处理设备两部分；运行环境、镜像及安装命令在计算服务模块文档中维护，不在页面展示。已安装模型隐藏重复下载入口；CPU 可主动选择，也提供自动降级开关与试跑验证；该策略与视频转码共用，保存时保留当前加速方式和修订号。环境与驱动预装，模型操作不在线安装依赖。未通过当前环境试跑的后端不会启用生成；OpenVINO 已接入但 Intel GPU 真机待验收，RKNN 按已部署模型与真机试跑结果显示资格。相关行为测试见 `tests/audio-processing.test.ts`、`tests/audio-roles.test.ts` 与 `tests/song-detail.test.ts`。

全部歌曲的桌面明细表及手机卡片在歌名前显示封面缩略图，通过同源接口读取已确认封面（含已确认的内嵌封面），图片延迟加载；无封面、元数据过期或图片加载失败时显示占位图。

原唱与伴奏页面保留歌曲和生成任务；旧 `?tab=setup` 入口跳转 `/system/compute#audio-models`。歌曲明细表展示封面、来源与文件、音轨编码/声道、原唱伴奏状态和最近生成任务；手机使用同一数据紧凑展示。分页常驻，默认 30 首，可选 20/30/50/100，支持跳页，跨页勾选继续保留，筛选时清空选择。性能节点配置集中管理连接、硬件策略和伴奏模型，仅显示实际检测到的加速硬件及必要的 CPU 降级配置。

扫描音轨默认为快速识别（明确标签优先、PANNs 先三个、证据不足最多六个短片段的双轨对比分类），不确定保留待确认。单曲面板区分“快速识别”与显式“深度识别”：前者不依赖分离设备试跑，后者需要已就绪的 Demucs 环境。任务历史显示 FAST/ANALYZE 类型、原因及折叠依据；快速模型未安装时提示性能节点配置，不自动启动深度任务。节点配置单独展示可下载/导入的快速分类模型，其就绪状态独立于伴奏生成设备；分类分数不作为准确率展示。

性能节点的模型配置入口依据 `media-probe` / `audio-role-fast` / 旧版 `audio-separation` 任一能力开放。`audio-separation` 只代表已通过试跑的分离能力，不能作为进入模型下载与试跑页面的前提，否则重启后资格失效会造成配置入口无法打开。空能力或未连接节点仍不读取模型设置。

节点启动会后台自动检查并试跑已安装模型；伴奏配置页显示自动检测/等待空闲状态，仍可查看试跑结果或手动重试。双音轨面板新增“试听音轨 1 / 2”与共享播放器，直接按源音轨 ID 请求同源授权 HLS，不依赖角色识别或 Demucs 就绪。切换时保留时间，只保留一个试听会话，停止、换歌或关闭时释放；无法保证选轨的原文件直放回退不会冒充选定音轨。试听沿用实时播放的优先级和租约，需要可用的计算节点。

内置助手形象支持本地待机动画：13 款图片形象使用透明底 2×2 四帧图集，呈现眨眼与手部/配件动作；原有团子支持呼吸、眨眼。点击入口有短暂回应，拖动和页面后台时暂停待机动画；系统开启减少动态效果时显示静态图。配置列表及欢迎面板保留静态展示，动作图加载失败回退静态形象。

管理端视频播放的进度、音量、原唱/伴奏、编码与设置集成在画面底部浮层，桌面端仅在鼠标移入播放器时显示，移出即隐藏，暂停或展开设置也不会保持显示；触屏设备常显。全屏使用同一套控件，音频播放保留独立控制区。

管理端 HLS 播放与音轨试听优先使用可用的 hls.js/MSE；MSE 不可用时才回退浏览器原生 HLS。浏览器报告 `canPlayType` 支持并不保证能解析尚在生成的 EVENT 清单，验收需覆盖冷启动、缓存命中、跳转与暂停恢复。NVENC H.264 的编码修复还需同步更新 Go 与 compute，见[计算服务说明](https://github.com/mynora-dot/singverse-compute/blob/main/README.md)。


## 电视首页设置

「客厅 → 电视首页」`#/system/tv-settings` 提供即时预览。支持多张首页封面上传、预览、名称、启停、排序、移除，及标题、说明、轮播开关和间隔；所有登录同一 NAS 的电视共用配置。上传即保存，其他草稿须点击保存；有草稿时先保存再上传/移除。管理操作复用Cookie与CSRF、版本冲突提示及离页草稿确认。TV读取新后端`/api/v1/tv/home`的`appearance`，约30秒同步或手动刷新。图片和配置在业务数据库内，须同步发布新版后端与完整前端。

封面选择支持一次多选，整批先校验剩余数量（最多8张）及格式/大小，再逐张提交并更新版本。显示上传进度；失败立即停止，保留已成功图片并提示文件名与原因，重新加载核对后再重试剩余图片。单张 JPEG/PNG 不超过2MB。

## 歌曲缓存

「设置 → 存储与缓存」`#/library/cache` 展示 NAS 保存的 WebDAV 原片块和完整音视频兼容结果，包括歌曲、格式/画质上限、实际缓存大小、命中次数、生成/最近使用时间和使用状态；列表每页20份。原片显示有效已缓存/源文件字节数及是否完整，部分缓存不能冒充整首。损坏或待清理文件通过可选 `residueBytes` 单列残留占用，不计入有效缓存字节和完整度；顶部实际占用仍包含这些残留。已有相同参数的整曲 HLS 缓存时，跳转播放继续复用；不同画质、音轨、字幕或独立生成的片段可能保留多份缓存。播放器与音轨试听按原曲位置减去资源 offset 定位。容量概况包含正在接收的数据。默认预算为 50 GiB；尚未手动保存设置时，每次启动检测缓存磁盘可用空间，不足预算则使用剩余空间的 80%，手动保存后重启保留设置。

管理员可配置共用容量（GiB，1GiB=2³⁰ bytes）、混合评分 HYBRID 或手动 MANUAL，及整数高/低水位（默认90%/75%，1≤低<高≤100）。旧自动策略统一迁移为混合评分；设置显式保存，带revision冲突和离页草稿保护。混合评分由真实播放热度H、实际活动最近程度R、近7×24小时有效频次F组成，权重0.4/0.4/0.2，列表展示生命周期和评分；3天软保留为衰减加分。固定、近24小时实际播放及正在播放/下载的数据受保护，预取和缓存访问不增加播放热度。

容量与操作集中在顶部，设置默认收起；展开后显式保存，收起或离页时保护未保存草稿。缓存明细与固定歌曲在同一区域切换，关键词和类型仅筛选当前页；两种视图独立使用服务端分页。点击歌曲可展开完整规格、使用记录和播放评分。手动策略禁用按策略回收，仍可显式清理；占用或评分统计未就绪时显示准备状态并禁用删除。

缓存明细与固定歌曲共用曲库的封面组件，按歌曲编号从同源元数据接口延迟加载缩略图；尚无缓存的固定歌曲也可显示已确认封面。缺少歌曲编号、暂无封面或加载失败时使用占位图。

固定按歌曲生效，覆盖原片/HLS全部现有及未来变体，不强制下载整曲；固定歌曲视图可取消暂无缓存或已下架歌曲的固定。单份删除须先取消固定，近24小时保护需勾选再次明确确认，仅覆盖指定缓存；播放/下载保护不可绕过。清理全部与按策略回收使用后台任务，显示等待、进行、取消、部分失败、保护阻塞及释放字节；离页停止前端轮询，后台继续，重新进入可恢复未完成任务。未达到目标水位和实际空间不足分开展示，保留每类跳过与失败说明，失败或保护阻塞时自动展开任务详情。

WebDAV 源文件和已有离线兼容版本保留；播放所需缓存下次按需重新读取或生成。全部请求通过同源 Go `/api/v1/transcoding/cache`，变更复用管理员 Cookie 与 CSRF。计算节点离线仍可管理已有缓存；目录或固定列表读取失败独立提示，不伪装成空列表。
TV 聚会队列在当前歌曲有效播放且剩余约 30 秒时，由 Go 提前缓存首个待唱歌曲的原片，覆盖手机扫码 H5 点歌形成的同一队列。排序、撤歌、切歌、停止和散场会更新或释放预取目标；预取不改变队列播放顺序，失败不影响当前歌曲。手机本机播放器仍为单曲模式，没有新增独立播放队列。

行为与API检查见 `tests/song-cache.test.ts`、`tests/song-cache-api.test.ts`；管理员主媒体按5秒播放/15秒暂停心跳采集，换轨和资源重建复用同一逻辑实例，伴奏不重复采集。日期从首次实际播放的 UTC 起点加单调墙钟推导；每条快照固定发生时间，暂停冻结最后实际活动时间，排队/重试不会延长近期保护，慢注册也保留原时长。参见 `tests/playback-activity.test.ts`、`tests/song-video.test.ts`、`tests/audio-track-preview.test.ts`。

## 播放记录与缺歌反馈

「客厅 → 播放与热门」`#/library/playback-history` 提供热门排行、播放明细及单曲历史，共用歌曲/歌手关键词和近 7 天、近 30 天或全部时间筛选。排行来自实际播放的持久明细，界面不使用演示数据；TV、手机和管理员预览采用受权实例与单调实播墙钟，旧队列不推算成播放历史。管理员试听只更新缓存活动保护和最近播放，不计有效次数或热门。

「客厅 → 缺歌心愿」`#/library/missing-feedback` 支持管理员登记、搜索和按待处理/处理中/已补齐/已关闭筛选。处理时可填写备注，标记已补齐须关联现存曲库歌曲，也可重新打开反馈。原始反馈保留，写入使用管理员 Cookie 与 CSRF，过期 revision 返回冲突。不会自动获取或下载歌曲，详见[功能与边界](contracts/song-activity.md)。

## 大曲库索引与请求生命周期

“原唱与伴奏”的歌曲列表读取 Go 后台构建的轻量索引；首次未就绪返回 503 和 `Retry-After: 1`，页面展示准备状态并重试。已有索引刷新时继续显示当前页，响应 `generation/building` 标记版本和更新状态。筛选结果只为当前页读取歌曲、角色及任务详情。

创建批次返回 202 和 `PREPARING`，展示 `prepared/selectionTotal` 及准备失败原因；准备完成进入 `PREVIEW` 后才允许确认生成。关闭弹层后准备继续，可在任务页重开；显式取消会停止后续准备，保留已完成伴奏。重启时未完成准备标为失败，需重新选择。

共享请求 ID 使用 `crypto.getRandomValues()` 生成 RFC 4122 UUID v4，支持普通 NAS HTTP 页面。亲友退出、切换邀请及组件卸载时取消在途请求，并用会话版本拒绝迟到响应；已确认操作也不会被更早的轮询结果或错误覆盖。结果不明确的点歌沿用原请求 ID 重试，发送期间保留该请求。亲友 HTTP 超时覆盖响应体读取，并清理取消监听。

停止等确认期间锁定重复操作，离页后不再执行尚未确认的动作。音频准备取消后忽略旧轮询，提交期间锁定确认弹层；歌曲索引的 503 重试在 KeepAlive 隐藏页签及离页时停止，返回歌曲页后恢复。

### 快速伴奏模式、试听与版本

新节点提供“极速档 / 干净档 / 高级档”；极速档提示中心抵消损伤，干净档使用固定 MDX，旧 HTDemucs 高级档保留。歌曲详情可明确选择已确认的源音轨/声道直接提取，生成 12 秒试听、整曲 AAC 或 FLAC 导出；旧成功版本保留，只有完整 AAC 可设为当前伴奏。批量确认与重试保存原配方，不把 DSP 与 AI 成果混用。旧节点保持原请求。`tests/audio-separation.test.ts` 覆盖无 Demucs 的 DSP、主动 CPU、FLAC、版本和源声道确认；详见 [伴奏引擎](https://github.com/mynora-dot/singverse-compute/blob/main/AUDIO-SEPARATION.md)。
